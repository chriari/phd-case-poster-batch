# phd-case-poster-batch 博士案例海报批处理

把博士申请过程中的**套磁回复 / 面试邀请 / Offer** 截图,批量转成「乐意轻学」品牌海报的 WorkBuddy skill(工作流)。

- 自动识别截图 → 分类(绿/紫/蓝)→ 联网核实最新排名 → 按定稿版式在 Ardot 画布构建 → 导出 PNG
- 敏感信息(姓名/邮箱/签名/研究方向)自动灰白马赛克打码,关键句红框圈出
- 输出文件名与原图完全一致,保存在 `输入文件夹/YYYY-MM-DD/`
- 原图保留在原文件夹,不删除、不移动

---

## 安装(一次性)

```bash
git clone https://github.com/chriari/phd-case-poster-batch.git \
  ~/.workbuddy/skills/phd-case-poster-batch
```

> 需要本机已安装 WorkBuddy(具备 Ardot 画布设计能力)。

## 环境准备(首次使用 / 同事必看)

本 skill 依赖 **Ardot 画布能力**,首次使用请按以下步骤确认环境:

1. **完成 Ardot 授权**:WorkBuddy 首页 → 新建任务 → 选「设计创意」Tab → 首次会弹出 Ardot 授权确认窗口(登录手机号自动关联,无需单独注册),点「确认」。
2. **必须新开会话**:Ardot 的函数级工具(`open_design` / 节点构建 / `export_nodes` 等)**只在会话创建时注入**。授权发生在会话中途不会补进当前会话,需要**新建一个任务/会话**,工具列表才会带上 Ardot。
3. **验证工具就绪**:在新会话里发一句「帮我新建一个 Ardot 设计文件」——能弹出画布/正常执行,说明 Ardot 已就绪;如果回复"没有 Ardot 画布能力"或退化成普通预览,说明还未授权或会话不对,回到第 1、2 步。
4. **再跑本 skill**:工具就绪后,再说「处理 [文件夹路径] 里的博士申请截图」。

> 注意:Ardot 是 WorkBuddy 内置能力(设计创意模式),不需要下载 Ardot 客户端;「连接器中心」里没有 Ardot 连接器。

## 使用

1. 把待处理截图放进**你指定的文件夹**(可随时更换,不写死任何路径)
2. 在 WorkBuddy 会话里说:「处理 [文件夹路径] 里的博士申请截图」
3. AI 会**先向你说明本次运行方式**,然后自动执行:
   - 读图并识别学校/类型(截图信息优先于文件名)
   - 分类:普通回复→🟢绿 / 面试邀请→🟣紫 / Offer→🔵蓝
   - 联网核实最新 QS / U.S. News 排名(仅排名 ≤200 时展示)
   - 在 Ardot **新建文件**、按定稿版式**从零构建**每张海报
   - 导出 PNG → 像素校验 → 存入 `输入文件夹/YYYY-MM-DD/`

## 设计规范

版式、配色、字体、水印、打码、红框的完整参数见 [references/template-rules.md](references/template-rules.md)(2026-08 年轻互联网版)。
逐节点施工图(含校名胶囊宽度上限)见 [references/build-spec.md](references/build-spec.md)。

### 新建批次的施工要点(实测最快最稳的做法)

1. **每张海报 2 次 `batch_edit`**:Ardot 的 binding 只在同一次调用内有效,所以
   - 第 1 次:建 10 个结构节点(海报 Frame → Hero → RegionRow/RegionDot/RegionText/PosterTitle/SchoolChip/ChipDot/SchoolText → ContentCard),**从返回结果里读真实 id**;
   - 第 2 次:用上一步的字面 id 建卡片内容(DearRow/Line2/HighlightBox/HL1/HL2/Line3/Line4/SigRow)+ 4 个水印 + Slogan。
   15 张 ≈ 30 次调用。给每张 frame 设不同的 `x`(0 / 1160 / 2320 / …)避免"节点重叠"警告。
2. **SchoolChip 不用 Move**,直接作为 Hero 第 3 个子节点建(几何上永远不和卡片相交,详见 build-spec 第六节)。
3. ⚠️ **插子节点时父 id 千万别写错**——实测把 ContentCard 的 id 写成了相邻的 SchoolText id,红框/落款全插进了文本节点,Ardot 报 `width="fill_container" requires the parent to use auto-layout`。看到这个报错就是插错父节点了:把插错的节点 `D` 掉重插即可。
3.1 ⚠️ **更隐蔽的一种父 id 写错:水印/Slogan 掉到页面顶层,而且不报错**。实测建"于洋-UWA"时把 WM×4 的父写成了上一张海报的 Slogan id,结果这 4 个水印变成了 Page 的直接子节点,`x=180/640` 在**页面坐标系**里生效,直接飘到最左边那张海报(CMU)身上盖住内容。**所以建完一批后必须验一次结构**:每张海报 Frame 的直接子节点应为 `Hero + ContentCard + WM-A/B/C/D + Slogan`(共 7 个)。若某个 frame 少了水印、页面顶层多了 WM 节点,用 `M(节点id, 海报frame的id)` 移回去即可(移完 x/y 是绝对坐标,会保持 180/600 不变,不用重设)。
4. **卡片高度统一放到最后一步**:先按预估字号建完(高度用 `hug_contents`),全部量完再一次性把 15 个 ContentCard `U` 成同一个固定值(本批 = 870)。这样只需一轮校准。
5. **校名胶囊会溢出**:可用宽度只有 936,胶囊右边界必须 ≤ 1008;长校名(如 `加州大学圣塔芭芭拉分校｜USNEWS100`)要把该张 SchoolText 降到 42~48px。
6. **导出后跑一遍脚本校验**(比逐张截图便宜):
   - **量卡片真实高度(用来判断有没有超长)**:从 `y=1439` 向上扫,找最后一个 `x=300/540/800` 三点全部 `R,G,B ≥ 253` 的行 → 那一行就是卡片底边。**为什么可靠**:卡片是纯白 255,而海报底色是浅渐变(最深只到 ~250/252),不会误判。`底边-470` = 卡片自然高;**> 870 就是放不下,`=1439` 说明已经溢出画布**。
   - 设成固定高度后,底边应统一 ≈ **1338/1340**(卡片底边对齐);
   - 扫 y=330~415,每行从右往左找第一个白色像素取最大 x → 应 **≤ 1008**(胶囊没溢出);
   - 缩略图拼成一张对照图目视整体一致性;
   - Ardot 导出的 PNG 是 **P 模式(调色板)+ 透明**,必须先 `convert("RGB")` 再保存;源图是 `.jpg` 的用 JPEG(q95)保存。

## ⚠️ 注意事项(踩过的坑,务必遵守)

### 0. 正文气泡高度固定(不许跟着文字缩)
- 海报纸张上的白色正文卡片(ContentCard)高度**写死一个固定值**,**禁止 `hug_contents`**。规格满高 **870**(卡片底边 y=1340,与 slogan y=1382 间距 42);李晨瑞-MSU 那张是 **877**,7px 差异肉眼不可见。
- 原因:文案短的邮件会让卡片跟着变矮,卡片底边在 900~1450 之间乱跳,一整套海报放在一起忽长忽短,非常难看。
- **同一批次内必须用同一个值。** 返修既有批次时,先读该批其它海报用的固定值并沿用(9-7补 = 877,9-11 = 870)。
- 文案短就下半部分留白,这是刻意的。若发现已有海报气泡偏矮 → 把该 ContentCard 高度改成批次值重新导出即可。

### 0.1 文字太长:先缩字号,别删内容,别硬塞
- 反面案例:邮件太长,为了「全部塞下」把卡片撑到超出 1080×1440 画布 → 正文显示不完整、落款马赛克和底部水印/slogan 撞在一起。
- **正确顺序**:
  1. **先把正文字号调小**(34 → 32 → 30 → 28 → 26),同时可把卡片的 itemSpacing 22 → 16、必要时收一点上下内边距,这一步**一个字都不删**。测量自然高度时先保持 hug_contents + `capture_layout`,放进目标高度后改回固定值。
     - 经验值:卡片自然高约 980 → 字号 30 可放下;约 1100 → 需要 28。**不要再低于约 26px** —— 再小就和其他海报明显不一致了,改走第 2 步。
     - 极端超长(自然高 900~1050)可以直接上**组合拳**:正文字号 → **26**、卡片 `itemSpacing` → **14**、`padding` → `{left:60,right:60,top:44,bottom:32}`。实测 HKBU(≥969)这样一改降到 **797**,UCL(896)→818,Curtin(910)→773,都留出足够余量。
     - 单看 itemSpacing:每减少 1 个 gap 单位就省 1px(卡片里有 4~5 个 gap,所以 22→14 大约省 32~40px),是"不缩字号就能救回来"的首选手段,对轻微的 870→874 这种超额(Adelaide)尤其管用。
  2. 缩到最小仍放不下 → **先问用户能不能删哪一句**,列出建议删的句子等确认。**严禁自己删有意义的段落。**
- 只调正文(DearText / Line2 / HL1 / HL2 / Line3 / Line4),**不动大标题(110~116px)和学校胶囊(52px)**。

### 0.4 非截图输入:PDF 录取信(Offer)
- 输入偶尔不是截图而是 **PDF 录取信**(如 `吴钺otago.pdf`)。处理:`pymupdf` 抽文本 + 渲染成图自己读,判定为 **蓝色 Offer 模板**(`博士OFFER来啦!`)。
- Offer 信通常**没有称呼语**(直接 "Congratulations! …"),这时**不要硬造 DearRow**,正文直接从 `Line2` 开始;红框里放**录取项目 / 开学日期 / 学制 / 学费**这些硬信息,`Line4` 用信里的落款语(如 `Yours sincerely,`)+ 签名马赛克。
- 输出文件名 = 原 PDF 名把扩展名换成 `.png`(如 `吴钺otago.pdf` → `吴钺otago.png`),原 PDF 一样保留不动。

### 0.5 一张截图 = 一张海报(默认不合并)
- **用户明确口径(2026-09-16)**:收件箱里每张截图都要出**自己的一张**海报。`Xxx University.png` + `Xxx University2.png` → **两张**海报,输出名和输入名一一对应。
  - 反面案例:9-16 批次把「导师先说聊一下」+「导师后定周一 10:00」两条同 thread 的截图合成了一张,用户要求拆开,最后重做成两张。
  - 即使是同一 thread 的上下两段(先约、后定时),**也默认各出一张**;想合并必须**先问用户**。
- **唯一例外:字节完全相同的重复图**。用 **MD5** 判断(别用肉眼看),如 `蒋元萍University of Macau.png` 与 `... 2.png` MD5 一致 → 只出 1 张,并在报告里说明。
- 收尾报告里**必须写清 `N 个输入 → M 张海报`**,并逐条列出被"吸收"的输入文件及原因(重复 / 用户同意合并)。

### 0.2 校名翻译要译全
- 英文校名**整段译成中文**,包括跟在后面的州/省/城市名。半翻译是错的。
- `Queen's University, Ontario` → `女王大学(安大略)`,**不能只写「女王大学」**,也不能写成「女王大学 Ontario」。
- `University of California, Berkeley` → `加州大学伯克利分校`。

### 0.3 返修既有海报(比重建快得多)
- 批次做完后用户常会要求"把某几张改一下"。**不要重建**——只要那个批次的 Ardot 文件还在(URL 里的数字 id,如 `.../file/724599205974027`),直接 `open_design` 打开 → 读 frame 拿到节点 id → 改属性 → 重新导出即可,内容 100% 不用重做。
- 两个必踩的坑:
  1. `export_nodes` 的 `nodeIds` 必须传 **frame 的 id**(如 `3:126`),传 ContentCard 的 id 只会导出 960×877 的卡片局部图。导出后确认尺寸是 1080×1440。
  2. Ardot 导出的 PNG 回来可能是 **P 模式(调色板)+ 透明**,直接当 RGB 用会报索引越界;需 `convert("RGB")` 后再保存,`.jpg` 的原图要用 JPEG 保存(禁止 PNG 字节写进 .jpg)。
- 覆盖前先把旧版海报备份到同目录的 `备份-气泡修改前/`,方便回退;源截图始终不动。

### 1. Ardot 渲染污染(最大的坑)
- **严禁 Copy 样板 frame 来生成海报**——复制后再改 Hero 文本,渲染会串内容(截图/导出显示别的海报的标题,但节点数据是对的),表现为"两张海报内容互相串"。
- **正确做法**:
  - 每次批次**新建一个 Ardot 文件**,不要复用渲染出问题的旧文件
  - 每张海报用 **Insert(I) 从零构建**,一个节点一个节点建
  - 全部建完再导出;导出 scale=1 得 1080×1440 PNG
- **像素校验**:导出的 PNG 与已知正确参照做像素对比——同内容参照差异应 <5%,不同内容参照应 >8%。如果两张内容不同但差异很小,说明渲染串了,弃用该文件重开。

### 2. 字体依赖
- 海报使用 Ardot 内置字体:`Sarasa Gothic SC`(中文)+ `Inter`(数字/英文)
- **换机器/同事首跑**:先只做 1-2 张测试图,确认字体渲染正常(缺字体会 fallback 成别的字体,效果完全不一样),再批量。

### 3. 输出格式
- `.jpg` 的源图:导出的 PNG 必须**转成真 JPEG** 再保存,禁止把 PNG 字节写进 `.jpg` 文件。
- 输出文件名与源图**一字不差**(含大小写/空格/中文/扩展名),不重命名。

### 4. 排名核实
- 每次生成前**联网核实最新排名**:美校用 U.S. News,其他地区用 QS。
- 排名 >200 或整榜都超 200 时,只写学校中文名,不写排名。
- 不写年份、"世界大学排名"、"第"。
- 中外合办院校地区标签用 `中外合办-PHD`,禁止用 `中国-PHD`。

### 5. 隐私与打码
- 姓名、邮箱、电话、ID、申请号、签名等 → 灰白圆角马赛克块(不留任何文字残留,不写"姓名已隐藏"等占位文字)
- 学生 RP 具体题目/研究方向、导师具体研究方向/项目/基金/实验室/独特课题 → 必须打码;宽泛学科可保留
- 任何可反向定位导师的细节,拿不准就打码
- 报告/README 中不暴露被打码的个人内容

### 6. 原图保留(安全)
- **原图一律保留在原文件夹,不删除、不移动**;海报单独存到 `YYYY-MM-DD/` 输出文件夹,两者并存
- 海报仍需 9 项校验(文件存在/可打开/竖版/模板正确/标题学校清晰/无个人信息/无RP细节/红框不遮字/文件名一致/含义未篡改)
- 任何一步失败:报告失败项,不影响原图
- 输出同名已存在:不覆盖,报告冲突
- 不做定时/自动监控,仅在用户明确要求时运行

### 7. 路径与共享
- 输入文件夹**由用户每次指定**,skill 内不硬编码任何人的桌面路径(方便同事共享使用)
- 每次运行前必须先向用户说明本次用法(见 SKILL.md 的 Usage briefing)
